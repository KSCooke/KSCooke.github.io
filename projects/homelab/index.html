A self-hosted home network

A personal project, started in October 2026: one old laptop running the network services for a family home, all of it rebuildable from a single Git repository.

What it does

  • DNS and DHCP for the whole house with Pi-hole, including ad and tracker blocking that differs per person and per device type, and a fallback path back to the router if the laptop ever fails.
  • Friendly internal names over HTTPS. Caddy sits in front of every service and signs internal names with its own certificate authority; nothing is exposed to the internet.
  • A family page where a family member can pause ad blocking on their own device for a few minutes when a site breaks, with an automated report afterwards on what the pause was for.
  • Home Assistant for lights, the alarm system and small automations such as printer-ink reminders.
  • Monitoring and alerts (Beszel, container health checks, a DNS watchdog, new-device alerts) sent to a phone.
  • Encrypted off-site backups with restic and Backrest, and a self-updating, searchable wiki that documents every piece.
  • A self-hosted travel planner for the family, and remote access from a phone over a WireGuard-based VPN.

How it's run

Every service is a pinned Docker Compose stack bound to localhost behind the reverse proxy. Changes to DNS and DHCP go through scripts that show a dry run first and never delete, with a configuration backup taken before every change. Because the laptop is the house's single point of failure for internet access, resource limits keep heavier apps from ever starving DNS, and every change ends with a check that lookups and blocking still work.
